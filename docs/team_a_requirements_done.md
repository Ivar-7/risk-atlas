# Team A PDF requirements completed

Source: [Nairobi Urban Flood Challenge — Team A problem statement](../data/Team_A_Nairobi_Problem_Statement%20%281%29.pdf), especially sections 2, 5, 7, 9, and 11. This checklist covers the required prototype and deliverables; the PDF's suggested technologies and stretch ideas are not requirements.

| PDF requirement | Completed work and evidence |
| --- | --- |
| **Ingest Nairobi flood hazard data.** | The model reads the starter kit's five 0–1 pluvial susceptibility tiers with the 600-building synthetic exposure and uses the supplied GeoTIFFs for added locations. The values are labelled as a constructed proxy, not observed depth. [Ingestion](../server/app/engine/ingestion.py) · [Hazard lookup](../server/app/engine/hazard_validation.py) · [Assumptions](assumptions.md) |
| **Explain how proxy severity becomes damage input.** | Each score is converted to an illustrative depth using `score × 4 m`, an explicit assumption from the PDF's example. The five tiers and assumed return periods are documented. [Model parameters](../config/model_parameters.yaml) · [Assumptions](assumptions.md) |
| **Apply a sourced vulnerability function for building types.** | The model interpolates the published JRC Africa residential depth-damage points and applies separately labelled assumptions for four construction classes. It exposes a vulnerability matrix, a score-to-damage chart, and damage ratios for each location and tier. [Vulnerability chart](../client/src/components/ui/dashboard-4-utils/vulnerability-chart.tsx) · [Vulnerability engine](../server/app/engine/vulnerability.py) · [Model parameters](../config/model_parameters.yaml) · [Assumptions](assumptions.md) |
| **Run a synthetic exposure portfolio.** | The 600 starter buildings have locations, construction classes, insured values, and tier scores. Imported rows are validated; reviewed free-text additions are marked synthetic. [Exposure data](../data/exposure_nairobi_with_hazard.csv) · [Ingestion](../server/app/engine/ingestion.py) · [Portfolio runner](../client/src/features/model/CatModelRunner.tsx) |
| **Calculate and aggregate property losses across flood tiers.** | For each building and tier, the pipeline combines hazard, vulnerability, and TIV, then sums ground-up and gross insured losses for the portfolio and construction classes. [Pipeline](../server/app/engine/pipeline.py) · [Financial engine](../server/app/engine/financial.py) |
| **Show financial terms and a return-period/EP curve.** | The portfolio model applies assumed per-property deductibles and limits, separates ground-up from gross insured loss, and shows scenario losses and an illustrative EP curve. Quota share, catastrophe excess of loss, and net loss are available in a separate single-occurrence document calculator; treaty structuring and net-of-reinsurance portfolio curves are outside the PDF's Team A scope. [Loss curve](../client/src/components/ui/dashboard-4-utils/revenue-chart.tsx) · [Document calculator](../server/app/engine/loss_terms.py) · [Assumptions](assumptions.md) |
| **Use AI to materially change the result and show its contribution.** | A live `gpt-6-luna` preview extracted 25 Kibera buildings from a synthetic offer. After review, they added KES 20,000,000 TIV and increased the illustrative 1-in-100 gross insured loss by KES 1,768,524 versus the same run without those rows. The run records the offer, extracted group, model, response ID, and comparison. [Live evidence](live_ai_demo_evidence.json) · [AI demo instructions](ai_exposure_demo.md) · [AI evidence view](../client/src/components/ui/dashboard-4-utils/ai-evidence.tsx) |
| **Provide a clear results interface.** | The dashboard shows total exposure, key return-period losses, the EP curve, construction-class breakdown, map, AI output and comparison, and assumptions. [Dashboard](../client/src/components/ui/dashboard-4.tsx) · [Workspace](../client/src/pages/DashboardPage.tsx) |
| **Identify data provenance, assumptions, and limits.** | The interface and written notes identify the portfolio as synthetic, the hazard as a proxy, depth and return periods as assumptions, and the drainage uplift as an unvalidated sensitivity. The common proxy flags 12 of 24 geocoded hotspot centres; no claim of measured pluvial depth or local claims calibration is made. [Assumptions register](../config/assumptions_register.yaml) · [Assumptions](assumptions.md) · [Submission note](submission_note.md) |
| **Submit a working demo and short note on sources, assumptions, and AI.** | The portfolio runner and dashboard form the demo; the written note covers all three requested topics. The live AI extraction and local reviewed API run are captured separately. [Submission note](submission_note.md) · [Live evidence](live_ai_demo_evidence.json) · [API guide](api.md) |

The EP frequencies, proxy-to-depth scale, construction adjustments, and policy terms are prototype assumptions. The live AI evidence used a local reviewed API run with database persistence mocked, so it did not add a demo record to the configured shared database.
